# Selfie on the RISC-R branch

This branch adds RISC-R (a reversible variant of RISC-U) to selfie as the tool riscr (`tools/riscr.c`), cellfie (`tools/cellfie.c`, an instruction-level reversible cellular machine that runs RISC-R), and bitr (`tools/bitr.c`, a BTOR2-only bounded model checker). The full development plan is `projects/reversible.md`; read it before changing anything on this branch. The instruction set is specified in `riscr.md`, next to `riscu.md`, and the cell machine in `cellfie.md`. The repo's `PLAN.md` is the course plan and belongs to the `intelligence` branch, not to this work.

## Design rules

Every change must obey these rules from the plan:

1. **C\* only.** Every tool compiles with selfie and with gcc, and runs on mipster, exactly as rotor and babysat do today. Check with `./selfie -c <file>` as well as `make`.
2. **One file per tool**, using `selfie.h` as its library. Shared code becomes one header.
3. **One spec per model of computation.** RISC-R semantics live in rotor's RISC-R machine model (M3); cellfie's cell rule is RISC-R per cell plus token movement. Everything else is checked against these two.
4. **Files are the only interfaces:** ELF binaries, RLE layouts, BTOR2 models. No tool calls into another tool's internals.
5. **Extend, don't fork.** RISC-R reuses RISC-U's 14 opcodes and encodings, marks its binaries with one ELF flag, and lives in its own tool, riscr, on top of `selfie.h`. Existing behaviour, make targets and grader tests stay unchanged.
6. **Every milestone ends in a check a machine runs**, as a make target, not a claim.
7. **Deferred on purpose:** asynchrony, hardware targets, performance.
8. **Reversibility is a switch.** Every tool runs with RISC-U and with RISC-R.
9. **Asynchrony stays below the semantics.** All semantics are synchronous steps.

## Conventions

- Selfie's coding style: C\* subset only (no `&&`, `||`, `!`, `+=`, `for`, structs, bitwise operators; use `not()`, `and()`, `or()`, `bitwise_xor()`, `left_shift()`, `get_bits()`), locals declared before statements, section banners, one blank line between statements, comments that state the semantics.
- `selfie.c` stays minimal: it only knows `EF_RISCR`, decodes `e_flags`, and refuses to run RISC-R binaries. All RISC-R code lives in `tools/riscr.c`, which follows `selfie.c`'s layout (library, compiler, interface, architecture, runtime, main) and has its own run loop, as monster does. Instructions are `do_riscr_*` procedures in its `RISC-R INSTRUCTIONS` section. Backward execution is the `reverse` flag: `instruction_address()` and `continue_at()` hide the direction.
- RISC-R in `tools/rotor.c` lives in `riscr_*` procedures in the `RISC-R` section and the RISC-R kernel next to the RISC-U kernel; `rotor_combinational` and `model_rotor` dispatch to them when rotor's own `RISCR` flag is set, by `-riscr` or by the ELF flag of a loaded binary. Rotor's `reverse` flag selects the direction of the generated model: `riscr_instruction_address()` and `riscr_continue_at()` hide it, so one set of procedures emits the forward and the inverse model.
- `tools/btor2.h` is the BTOR2 library shared by rotor and bitr: the model data structure, the BTOR2 and SMT-LIB printer, and the concrete evaluator. Both tools are built with `--include selfie.h --include tools/btor2.h` and compile with `./selfie -c selfie.h tools/btor2.h tools/<tool>.c`. Bitr (`tools/bitr.c`) reads BTOR2 and nothing else; programs and input enter it only through its loaders, `-l binary` and `-i file`, as initial state.
- Cellfie (`tools/cellfie.c`) is built like rotor and bitr, with `--include selfie.h --include tools/btor2.h`, and laid out as grid, token, cell rule, layout, simulator, model, check, main. The simulator states the rule in the `cell_*` procedures and `act`, the model in `model_rule`; both take the direction from cellfie's `reverse` flag, so one set of procedures runs and emits the rule and the inverse rule. The model is a decision tree of effects (`new_choice`, `new_effect`), by cell kind, then path or side, then instruction: keep it one, see the decisions of November 23, 2026. Layouts are the only way a grid enters or leaves cellfie.
- Testing code lives in `tests/`, never in `tools/` or `selfie.c`. The M1 harness is `tests/riscr-test.c`, built like a tool with `--include selfie.h --include riscr.h` (`riscr.h` is generated from `tools/riscr.c` as `selfie.h` is from `selfie.c`), and must itself be C\*.
- Options: `riscr` takes selfie's options plus `-t <binary>` (translate the loaded RISC-U binary into a RISC-R binary, which stays loaded), `-m <MB>` (forward) and `-rev <MB>` (forward and then backward, checking that the initial state is restored) for RISC-R binaries; there is no RISC-R flag in selfie. Rotor's options after `-` include `-riscr` (RISC-R machine model), `-inverse` (the inverse model), `-roundtrip <N>` (check inverse after forward and forward after inverse on N random states), and `-tapes`, `-tapewords`, `-syscallwords` to size the tapes. `riscr -history <MB>` sizes the history stack a translated program allocates (3072 by default), so that translated programs fit rotor's models. Bitr takes `model.btor2 [ -l binary ] [ -i file ] [ -k steps ] [ -p ]` and reports the first bad state or violated constraint with the number of instructions executed. With `-bmc <steps>` it checks all inputs symbolically (`-all` for every bad input, `-w file` to write the witness, `-dimacs prefix limit` to write the SAT instances, `-v` for progress); `model.btor2 -identity inverse.btor2` proves that the inverse model undoes the model; `bitr -sat file.cnf` runs its CDCL solver on a DIMACS file. Cellfie takes, in order, `-l layout`, `-o layout`, `-f ticks` (forward until a property holds), `-b ticks` (backward), `-rev ticks` (forward and as many ticks backward, checking that the state is restored), `-btor2 width height` (the rule as `cellfie-WxH.btor2`; after `-inverse` the inverse rule, after `-noproperties` the rule without its bad states), and `-check states` (simulator against model on random states).

## Decisions that refine the plan

- `addi rd,rs1,imm` means `rd += rs1 + imm`, not just `rd += imm`, so register moves into zeroed registers stay one instruction.
- `mul`, `divu`, `remu`, and `sltu` are `rd ^= f(rs1, rs2)` (self-inverse) rather than `rd += f`, because with `+=` no forward program can ever uncompute a comparison or a product, so every loop would leak a register per iteration. `add`, `sub`, `addi`, `lui` stay additive, each invertible by another forward instruction.
- Paired branches: a taken transfer lands *after* its come-from (`target + 4`), so no extra branch register is needed and the step function is a bijection on all states given the static pairing. The come-from of a `beq` may test different registers; its condition must hold at the transfer, checked dynamically.
- Calls: `jal rd` requires `rd == 0` and links `pc + 4`; `jalr rd,0(rd)` is the come-from of a call and also the return, uncomputing `rd`; the come-from of a return is a `jal ra` right after the call site pointing at the callee's return `jalr`. The translator finds the callee's epilogue as the first `jalr` after its entry (M2).
- System calls take arguments in `a1-a3` and add their result into `a0`; backward execution recomputes the result from the tapes and subtracts it. `exit` leaves the state unchanged; `read` exchanges words with a lazily filled input tape that remembers where the file ended; `write` appends to an output tape and still writes the file; `openat` allocates the next descriptor and a tape per file; `brk` requires `a0 == 0`, grows the heap and returns the previous break in `a0`, zero on failure. This is the M1 addendum of November 1, 2026; it changes the system call convention that M2's wrappers must emit.
- RISC-R binaries carry `EF_RISCR` (bit 8 of `e_flags`); mipster refuses them and riscr refuses binaries without the flag, instead of switching modes silently.
- Riscr does not write the context pointer into `a6` on context switches, so registers are bit for bit reversible; context switching, and with it hypster, stays unsupported until M17, which adds the from-context into a zeroed `a6` instead.
- November 2, 2026: the emulator moved out of `selfie.c` into `tools/riscr.c` to keep `selfie.c` minimal (M1 had added about 1,380 lines; about 10 remain). This refines rule 5: RISC-R is a tool on top of selfie, not a flag inside it. M2 followed the same way, as a translator from RISC-U to RISC-R binaries in `tools/riscr.c` rather than a second code generator in starc, see November 6.
- An instruction that throws an irreversible instruction exception has no effect; the control-flow inverses were checked by a randomized round trip (200,000 random states, forward then backward and backward then forward, no mismatch) on November 1, 2026, and `riscr.md` records why a branch register, even one hidden in `zero`, would not remove come-froms.
- November 6, 2026: M2 is the translator `riscr -t`, in riscr's compiler section, from RISC-U binaries as starc emits them; starc is unchanged. The scheme is the Bennett translation section of `riscr.md`: six reserved registers (`s2` history pointer, `s3` flag, `s4` one, `s5` program break, `s6`/`s7` scratch), one fixed RISC-R sequence per RISC-U instruction, a come-from chain plus one pushed flag per branch target, islands for transfers beyond the reach of `beq`, and a prologue that allocates the history stack (3GB, `HISTORY_GIGABYTES`) at the start of the heap with one `brk`. The translator finds a callee's return as the first `jalr` after its entry, so starc needs no second fixup chain. RISC-U `brk` semantics, including `brk(0)`, are reproduced from the program break register, so `malloc` and the bootstrap stay unchanged. Measured: 3.6 RISC-R instructions per RISC-U instruction statically, 3.5 dynamically; selfie compiling itself pushes 0.65 words per RISC-U instruction, 2GB in total, and reverses in about the time it took forward.
- `-rev` now takes a snapshot of the initial state at boot and checks it after backward execution (`take_initial_snapshot`, `is_initial_state_restored` in `tools/riscr.c`); `tests/riscr-test.c` uses the same procedures through `riscr.h`.
- `MAX_TAPE_SIZE` is 8MB: selfie reads source files one byte per `read`, which costs one tape word per byte. `MAX_CODE_SIZE` and `MAX_BINARY_SIZE` are four times selfie's in riscr, since RISC-R binaries are that much larger.
- `bitwise_xor` masks the bytes it loads from its table; with gcc `char` is signed, which made `mul`, `divu`, `remu`, and `sltu` wrong for bytes of 128 and above (found by M2, November 6, 2026).

- November 6, 2026, M3a: the RISC-R machine model is program-independent and its step function is total: on a state that violates a RISC-R rule the model still defines a next state, and a property fires in that state. There is one property per rule (`irreversible-aliasing`, `-store`, `-branch`, `-jump`, `-link`, `-return`, `-brk`, `-exit` in the inverse model only, and `unsupported-syscall`), emitted as `bad` when a binary is loaded and as `constraint` for the machine model without binary, following rotor's `state_property` convention. The constraints are what the symbolic identity proof in M5 assumes; the bad states are how translated binaries get checked. The inverse model is the same generator run with `reverse` set: it fetches at `pc - 4`, subtracts where the forward model adds, flips the same bits for `mul`, `divu`, `remu`, `sltu`, exchanges for `ld`, and lands on come-froms instead of jumping over them; both models share state names and sorts, as the BTOR2 profile requires.
- M3a refinements of the semantics: backward `brk` is only reversible on states in the image of forward `brk`, either `a0 != 0`, `a0 < brk`, `a1 == brk`, and `brk` at most the heap end, or `a0 == 0` and `a1` not a valid new break. Riscr only checks `a0 != 0`; the model is stricter and the round trip shows the extra conditions are needed (dropping `a1 == brk` fails). `exit` is excluded from the round trip in both directions: forward it stops the machine in place, which no step inverts, and backward it is irreversible by rule. `read`, `write`, and `openat` were `unsupported-syscall` until M3b.
- November 7, 2026, M3b: tapes are named state (`input-tapes`, `output-tapes`, `tape-heads`, `tape-ends`, `tape-inputs`, `tape-opens`, `open-files`), see the machine model section of `riscr.md`. Input tapes, file ends, and host opens are uninitialized, which makes them the model's input and keeps the model a closed system with no `input` lines. Two refinements keep every step a bijection without invariants: `write` is an exchange like `read` (on reachable states the words ahead of an output head are zero, so it copies, and riscr's copy-and-erase is the same there), and `openat` flips the tape kind by the kind the flags select instead of setting it. The model bounds the emulator's open sizes with `-tapes`, `-tapewords`, and `-syscallwords`, each with a bad state when exceeded, as rotor bounds memory with allowances. The round trip cannot see a wrong system call result that is added forward and subtracted backward; fidelity to riscr needs the whole-program comparison in M4.
- M3a implementation notes: rotor's evaluator updates arrays in place and evaluates `ite` lazily, so a step that reads and writes both registers and memory (`ld`) must evaluate its operands before either data flow; `-roundtrip` does this through structurally shared lines, nothing changes for the printed model. Rotor's `bitwise_xor` returned `a` for equal operands instead of 0, found by the round trip on `mul`; fixed. Selfie's `MAX_DATA_SIZE` is 128KB since rotor's string literals exceeded 64KB. The plan's move of the evaluator into `tools/btor2.h` is deferred to M4, where bitr first needs it.

- November 7, 2026, M4: the evaluator in `tools/btor2.h` logs array writes while evaluating and applies them with the next state (`log_write`, `apply_writes`), so all reads of a state within one step see the state before the step. It used to write in place, which was correct only as long as no step both read and wrote the same array in two data flows; RISC-R's `read` exchanging memory with tape words broke it, found by `make sim`. Reads through write expressions, which rotor uses to check initial values while building them, see the logged writes. The round trip no longer needs to pre-evaluate exchange operands.
- M4 notes: a RISC-R program's transient `sp` values (the exchange with a history slot leaves `sp` zero for one instruction) make rotor's stack pointer properties meaningless, so they are off in RISC-R mode. The RISC-R model gets rotor's exit code properties with the exit code in `a1`. `riscr -history <MB>` makes translated programs fit a model's heap allowance; `make sim` uses 1MB. Bitr counts the instruction that stops it: an exit is the n-th instruction when the emulator reports n, a faulting instruction is the (n+1)-th since emulators do not count it. Bitr's ELF loader checks every word against the words a rotorized model holds already, which checks rotor's initialization against the loader on every example; a code-free machine model with a binary's segmentation, where the loader would be the only source of code, needs a rotor option not yet written.

- November 14, 2026, M5: bitr's symbolic layer is in `tools/bitr.c` in the order bit blaster (and-inverter graph with constant folding and structural hashing, interned bit vectors, arrays as bases, writes, and choices with read over write), CDCL (two watched literals, first UIP learning with minimization, activity heap, phase saving, Luby restarts, clause database reduction), CNF (Tseitin encoding of the cone of influence, DIMACS in and out), bounded model checker, identity proof. The model checker does not unroll the model into one formula: it forks a path wherever the next value of a bit-vector state is a choice between constants, which is where the pc depends on input, and asks the solver whether a fork is feasible and whether a bad state is reachable on a path. Unrolling with a symbolic pc made every memory write a write at a symbolic address and did not scale past the first input-dependent branch.
- M5 on babysat: babysat enumerates assignments, so the comparison with CDCL is on instances with at most 100 variables, `examples/sat` plus what `-dimacs` writes; CDCL was also checked against babysat on 1,600 random instances, with restarts and clause deletion forced to happen early. There is no external SAT solver in the loop.
- M5 identity proof: all states are free and the two models share them by name. Values are bit vectors that do not depend on the path; every choice, an `ite` condition or the equality of a read index with a written index, is cofactored by what the path assumes (`aig_cofactor`) and splits the path if still undecided (`decide`, `prove_paths`). What an instruction and its inverse do is cancelled by structure where possible (`bv_add_normal`, `bv_sub_normal`, `bv_xor_normal`: `(x + v) - v`, `(x ^ v) ^ v`, constants added in a row; `arr_write` of what is there), so a multiplication is never handed to the solver; arrays are compared at the indices written. What is left goes to CDCL with the path's assumptions added lazily. About 1,000 paths forward then inverse, 1,300 inverse then forward, under 10 seconds each. One step only: two steps multiply the paths and did not finish in 10 minutes, and follow by induction anyway.
- M5 lessons on soundness: an earlier version cached values that had been simplified under one path and reused them on another, and reported both a proof and a bogus counterexample. Caches now only hold facts that are true on all paths. The proof was then tested by mutation: dropping any of nine constraints (aliasing, branch, jump, link, return, brk, and the segmentation faults of `ld`, `read`, `write`) gives a counterexample, running the forward model twice does too.
- M5 found, and rotor now has: the constraint `input-zero-beyond-end` (tapes are zero beyond the end of the file, otherwise RISC-R witnesses do not replay), `irreversible-brk` forward with a zero program break, `irreversible-brk` backward with a program break that is not word-aligned (a counterexample to forward after inverse that 100,000 random round trips did not hit), word-aligned memory access in the RISC-R model with the property `unaligned-address` (byte-wise access was most of the circuit), and `all-cores-exited` as a bad state of the RISC-R machine model. Rotor's RISC-U models are unchanged byte for byte.
- M5 fixed an M4 bug: bitr did not run on mipster, its file reader read into unmapped memory and took mipster's 32-bit -1 for a length. The buffer is now touched and a short read ends the file. Bitr's CDCL and BMC run on mipster with the native results.
- Instruction counts in witnesses follow M4's convention: an exit and a division by zero are the n-th instruction when the emulator reports n, a segmentation fault is the (n+1)-th.

- November 23, 2026: the encodings are frozen. RISC-R keeps RISC-U's 14 opcodes and encodings; the table of dedicated opcodes at the end of `riscr.md` stays a sketch. Cellfie comes before the rest of the RISC-R work (M9, M16, M17): nothing in cellfie depends on that work, M15 needs M8, and routing is the largest open risk.
- November 23, 2026, M6a, the cell rule (`cellfie.md` is authoritative): the grid is a torus with power-of-two sides; one tick is act, then move one cell, and backward move back, then undo. Wire is blank cells (which also cross wires), mirrors `/` and `\`, and routers, mirrors that act only if a bit of the token's pc or address is set. An instruction cell has an orientation and a mirror; it executes for a token on its path and is a mirror between its path and its side for a token that takes a branch, jumps, returns, or exchanges with memory. Every cell permutes the headings and is a bijection on the rest, so the rule is a bijection on all states and needs no constraint; bitr proves it without assuming anything.
- M6a, the token carries two words beyond pc and registers, both zero on a path: the address (origin of a transfer, or address of a memory word) and the datum (the register on its way to memory and back). In transit pc is the target and the address the origin, so a router is a merge by the origin on the way out and a split by the target on the way in, with no mode in the token. The cell at the target uncomputes the origin: a come-from `beq` or `jal` from its own pc and immediate, a `jalr` from its link register. A come-from is an instruction cell entered from the side, which is why origin and come-from being the same instruction suits the grid.
- M6a, where cellfie differs from riscr to stay total: `jalr` rotates pc, `rd`, and address instead of zeroing `rd` (the same when the address is zero); a token arriving at a come-from whose condition does not hold passes through, since a cell cannot check the other end of a wire; a division by zero leaves `rd` unchanged. Where a program stops is a property, not dynamics: `illegal-instruction`, `irreversible-link`, `division-by-zero`, `exit`, `unsupported-syscall` are bad states of the rule's model and where the simulator stops, and the rule is defined past them. The inverse rule has no properties.
- M6a, two statements of the rule, tied by a check: the simulator and the model are written separately, `-check` compares them tick by tick on random states, forward and backward, and bitr proves the model. Mutation testing: thirteen wrong rules fail the check; of eight wrong models the seven that are no bijections fail the proof, the eighth is a different bijection and fails only the check.
- M6a lesson on the shape of a model: the first model was flat, one `ite` chain per state over conditions like `on-path and is-add`, and bitr needed 155,363 paths and 2 minutes 39 seconds for one direction. As a decision tree, by kind, then path or side, then opcode, then the rules, with the same condition lines shared by all states, with the move computed from the bits of the heading rather than chosen by `ite`, and with a router's turn as an exclusive or, it is 80 paths and a quarter of a second, and 45 seconds for both directions on 64x64 cells. Bitr splits on every `ite` condition it cannot decide, and assuming a disjunction false or a conjunction true tells it nothing about the parts.
- M6a split the milestone as M3 was split: tapes and the system calls beyond `exit` are M6b. Rule 8 is open for cellfie: a layout names its rule in its header, and cellfie refuses `RISC-U` until RISC-U cells exist. An `ld` that is unaligned or has no memory cell is not detected.

## Open after M2

- The most negative immediate cannot be negated in one instruction, so uncomputing such a constant needs two: `-2^19` for `lui`, `-2^11` for `addi`. The translator never negates constants, it pushes.
- Riscr has no replay engine (`-r`); comparing trace-based undo with trace-free backward execution is a lesson still to be written (M15).
- The history stack is a fixed 3GB region; Bennett checkpointing was not needed for selfie and is not implemented. Programs that overflow it fail at the `brk` of the prologue (exit code 20) or run into their own heap.
- The translated bootstrap still executes RISC-U's two `brk` calls, now against the program break register; `malloc` keeps its RISC-U shape. A garbage-free M9 code generator would emit RISC-R system calls directly.
- Transfers beyond the reach of `beq` cost 9 instructions at the origin and 2 per origin plus 4 at the target; selfie has 28 of them.
- `riscr.md` ends with a table of how each instruction would look with dedicated opcodes; M2 confirmed the costs that table predicts: four `^=` instructions need the scratch sequence, and `jal zero` come-froms force islands.
