# Selfie on the RISC-R branch

This branch adds two things to selfie:

- **RISC-R**, a reversible variant of RISC-U, and its toolchain: riscr (`tools/riscr.c`) translates RISC-U binaries into RISC-R binaries, compiles C\* with statements that need no history, and executes RISC-R forward and backward. The instruction set, the translation, and rotor's machine model of it are specified in `riscr.md`, next to `riscu.md`.
- **Bitr** (`tools/bitr.c`), a BTOR2-only bounded model checker, and **entr** (`tools/entr.c`), the part of bitr that is being rebuilt on one principle, counting, and will become bitr's only engine. `bitr.md` has the principle, the theorem, the switches, the checks, what was measured, and what is next. Read it before changing bitr or entr.

There are no milestones and no deadline. The aim is a checker that is as simple as its principle and reaches performance through optimizations that can each be turned off. The repo's `PLAN.md` is the course plan and belongs to the `intelligence` branch, not to this work.

Parked: cellfie (a reversible cellular machine that runs RISC-R, with a layout compiler), bitr's product of two models and layout loader, backward checking in bitr, and the plans and decisions of all of it (`projects/reversible.md`, `projects/entropy.md`, `cellfie.md`, `optimizations.md`, and the long form of this file) are at commit `62593875eecf` of this branch. Nothing on the branch depends on them now.

## Design rules

1. **C\* only.** Every tool compiles with selfie and with gcc, and runs on mipster, as rotor and babysat do. Check with `./selfie -c <files>` as well as `make`.
2. **One file per tool**, using `selfie.h` as its library. Shared code becomes one header.
3. **One spec per model of computation.** RISC-R's semantics are rotor's RISC-R machine model; riscr and everything else are checked against it.
4. **Files are the only interfaces:** ELF binaries, BTOR2 models, DIMACS formulas. No tool calls into another tool's internals, except through a header generated from its source (`riscr.h`, `bitr.h`, `entr.h`).
5. **Extend, don't fork.** RISC-R reuses RISC-U's 14 opcodes and encodings and marks its binaries with one ELF flag. Existing behaviour, make targets, and grader tests stay unchanged.
6. **Every claim ends in a check a machine runs**, as a make target.
7. **Reversibility is a switch.** Every tool runs with RISC-U and with RISC-R.
8. **Every optimization is a switch.** The unoptimized version stays runnable as specification and baseline, and a switch lands with a check that on and off agree.

## Conventions

- Selfie's coding style: C\* subset only (no `&&`, `||`, `!`, `+=`, `for`, structs, bitwise operators; use `not()`, `and()`, `or()`, `bitwise_xor()`, `left_shift()`, `get_bits()`), locals declared before statements, section banners, one blank line between statements, comments that state the semantics.
- `selfie.c` stays minimal: it only knows `EF_RISCR`, decodes `e_flags`, and refuses to run RISC-R binaries.
- **Riscr** (`tools/riscr.c`) follows `selfie.c`'s layout (library, compiler, interface, architecture, runtime, main) and has its own run loop. It is built on `selfie-riscr.h`, which is `selfie.c` with `main`, `find_next_character`, `get_symbol`, `compile_assignment`, and `compile_statement` renamed by sed; riscr's procedures of these names, in its `COMPOUND ASSIGNMENTS` section, call selfie's and add `x += e`, `x -= e`, `x ^= e`, and `from (e1) while (e2) statement`. It compiles with `./selfie -c selfie-riscr.h tools/riscr.c`. Instructions are `do_riscr_*` procedures; backward execution is the `reverse` flag, hidden by `instruction_address()` and `continue_at()`. The translator is in the compiler section (`riscr -t`); a compound assignment is RISC-U code between markers in `s6`, classified as `TK_*` and emitted by `put_update` and `put_inverse`, and anything `put_body` learns to emit inside an expression needs its inverse in `put_inverse`.
- **Rotor's RISC-R model** lives in `riscr_*` procedures in the `RISC-R` section of `tools/rotor.c` and the RISC-R kernel next to the RISC-U kernel, selected by `-riscr` or by the ELF flag of a loaded binary. Rotor's `reverse` flag selects the direction of the generated model, hidden by `riscr_instruction_address()` and `riscr_continue_at()`, so one set of procedures emits the forward and the inverse model. The step is total: a state that violates a RISC-R rule has a next state, and a property fires in it, a `bad` with a binary loaded and a `constraint` without. Rotor's RISC-U models must stay unchanged byte for byte.
- **`tools/btor2.h`** is the BTOR2 library shared by rotor, bitr, and entr: the model data structure, the BTOR2 and SMT-LIB printer, and the concrete evaluator, which logs array writes and applies them with the next state. Tools are built with `--include selfie.h --include tools/btor2.h`.
- **Bitr** (`tools/bitr.c`) is laid out as parser, loaders, simulator, bit blaster (and-inverter graph, bit vectors, arrays), CDCL, CNF, bounded model checker, identity proof, DIMACS, main. It reads BTOR2 and nothing else; programs and input enter only through `-l binary` and `-i file`, as initial state. The model checker does not unroll: it forks a path where the next value of a bit-vector state is a choice between constants. Caches hold only facts that are true on all paths.
- **Entr** (`tools/entr.c`) is built on `bitr.h` (`tools/bitr.c` with its `main` renamed): `--include selfie.h --include tools/btor2.h --include bitr.h`, and `./selfie -c selfie.h tools/btor2.h bitr.h tools/entr.c`. It uses bitr's parser, loaders, and lines of a model and nothing of bitr's symbolic layer, and cannot use a name that bitr has. It is laid out as count, worlds, reference, formula, loop, bracket, estimate, main. A count is a record (`new_count`, `count_add`: a mantissa times a power of two, exact or a lower bound); entropy is only printed. Every count is over declared bits (`-over`, `-fix`, `-zero`; `check_declarations` refuses an open state that is not declared). The reference (`reference`, `set_world`, `run_world`) is the one trusted component. The loop is `count_region`; there are two knobs and no third: a switch is a rule of `bracket` or of `estimate`. A rule that makes a region smaller or disposes of it enters it in a ledger (`enter`), `ledgers_account` checks that the ledgers are all 2^n worlds, and `trace` writes the run as a file. A literal on the trail is supposed (`suppose_literal`, which opens a level) or implied by a clause (`imply_literal`). The loop goes back one region at a time, which keeps the ledger a check; a restart clears it. A new switch lands with its ledger, its event in the trace, its check in `tests/entr-trace.c`, and its lines in `make ledger`.
- **Testing code** lives in `tests/`, never in `tools/` or `selfie.c`, is C\*, and is built like a tool on the generated header of the tool it tests (`tests/riscr-test.c` on `riscr.h`, `tests/entr-trace.c` on `entr.h`).
- **Options.** `riscr` takes selfie's options plus `-t <binary>` (translate the loaded RISC-U binary), `-m <MB>` (forward), `-rev <MB>` (forward and then backward, checking that the initial state is restored), and `-history <MB>` (the history stack a translated program allocates, 3072 by default; 1 for programs that go into rotor's models). Rotor's options after `-` include `-riscr`, `-inverse`, `-roundtrip <N>`, `-tapes`, `-tapewords`, `-syscallwords`, and `-bytestoread`. Bitr's and entr's are in `bitr.md`.

## Checks

`make reversible`, part of `make more`, runs them one after another, since they share generated files: `rev`, `garbage-free`, `riscr-model`, `sim`, `bmc`, `count`, `ledger`, `bit-length`, `cdcl`, `identity`. `make riscr-rev` and `make bennett` (selfie translated to RISC-R compiles itself and runs back; about 7 minutes and 3GB) are separate. `riscr.md` and `bitr.md` say what each checks.

## What bit us

- **Selfie's limits.** A `while` or `if` body of more than 4KB of code does not compile (the branch around it does not reach), so long procedures are split; a string literal has a maximum length, so long `printf` formats are split; `char` is signed with gcc, so bytes loaded from tables are masked.
- **C\* on mipster** costs about 40 RISC-U instructions per procedure call and per loop iteration. Mipster runs are for checks, on small inputs; native runs are for numbers.
- **Instruction counts.** An exit and a division by zero are the n-th instruction when the emulator reports n; a segmentation fault is the (n+1)-th.
- **Input in RISC-R models.** A `read` exchanges whole words with the tape, a word per read of up to eight bytes, and the bytes beyond the size of the read are zero. A program that reads n bytes one at a time reads n tape words. The file that `bitr -w` writes for a RISC-R witness is the tape and replays in riscr only if the program reads once.
- **Specifications have bugs that only a second implementation finds.** Rotor's RISC-R model was wrong about `write` and about `read`, each found when a new tool ran a program that no check had run before.
- **Measure on the real instances.** Entr's loop looked fast on formulas of 100 variables and is not on the formulas of 100,000 variables that model checking generates.
