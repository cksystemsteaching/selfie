# Selfie on the RISC-R branch

This branch adds RISC-R (a reversible variant of RISC-U) to selfie as the tool riscr (`tools/riscr.c`), cellfie (`tools/cellfie.c`, an instruction-level reversible cellular machine that runs RISC-R), and bitr (`tools/bitr.c`, a BTOR2-only bounded model checker). The full development plan is `projects/reversible.md`; read it before changing anything on this branch. The instruction set is specified in `riscr.md`, next to `riscu.md`, and the cell machine in `cellfie.md`. `optimizations.md` explains what was optimized in RISC-R and cellfie with one running example (`examples/symbolic/recursive-fibonacci-1-10.c`) and numbers before and after; keep it up to date: a change that moves one of its numbers, or adds an optimization, updates it in the same commit, with the commit added to its table of layouts and to the list in `figures/render.py`, which renders its figures (`python3 figures/render.py`). The repo's `PLAN.md` is the course plan and belongs to the `intelligence` branch, not to this work.

## Design rules

Every change must obey these rules from the plan:

1. **C\* only.** Every tool compiles with selfie and with gcc, and runs on mipster, exactly as rotor and babysat do today. Check with `./selfie -c <file>` as well as `make`.
2. **One file per tool**, using `selfie.h` as its library. Shared code becomes one header.
3. **One spec per model of computation.** RISC-R semantics live in rotor's RISC-R machine model (M3); cellfie's cell rule is RISC-R per cell plus token movement. Everything else is checked against these two.
4. **Files are the only interfaces:** ELF binaries, RLE layouts, BTOR2 models. No tool calls into another tool's internals.
5. **Extend, don't fork.** RISC-R reuses RISC-U's 14 opcodes and encodings, marks its binaries with one ELF flag, and lives in its own tool, riscr, on top of `selfie.h`. Existing behaviour, make targets and grader tests stay unchanged.
6. **Every milestone ends in a check a machine runs**, as a make target, not a claim.
7. **Deferred on purpose:** asynchrony, hardware targets, performance.
8. **Reversibility is a switch.** Every tool runs with RISC-U and with RISC-R.
9. **Asynchrony stays below the semantics.** All semantics are synchronous steps.

## Conventions

- Selfie's coding style: C\* subset only (no `&&`, `||`, `!`, `+=`, `for`, structs, bitwise operators; use `not()`, `and()`, `or()`, `bitwise_xor()`, `left_shift()`, `get_bits()`), locals declared before statements, section banners, one blank line between statements, comments that state the semantics.
- `selfie.c` stays minimal: it only knows `EF_RISCR`, decodes `e_flags`, and refuses to run RISC-R binaries. All RISC-R code lives in `tools/riscr.c`, which follows `selfie.c`'s layout (library, compiler, interface, architecture, runtime, main) and has its own run loop, as monster does. Instructions are `do_riscr_*` procedures in its `RISC-R INSTRUCTIONS` section. Backward execution is the `reverse` flag: `instruction_address()` and `continue_at()` hide the direction.
- RISC-R in `tools/rotor.c` lives in `riscr_*` procedures in the `RISC-R` section and the RISC-R kernel next to the RISC-U kernel; `rotor_combinational` and `model_rotor` dispatch to them when rotor's own `RISCR` flag is set, by `-riscr` or by the ELF flag of a loaded binary. Rotor's `reverse` flag selects the direction of the generated model: `riscr_instruction_address()` and `riscr_continue_at()` hide it, so one set of procedures emits the forward and the inverse model.
- `tools/btor2.h` is the BTOR2 library shared by rotor and bitr: the model data structure, the BTOR2 and SMT-LIB printer, and the concrete evaluator. Both tools are built with `--include selfie.h --include tools/btor2.h` and compile with `./selfie -c selfie.h tools/btor2.h tools/<tool>.c`. Bitr (`tools/bitr.c`) reads BTOR2 and nothing else; programs, input, and layouts enter it only through its loaders, `-l binary`, `-i file`, and `-grid layout`, as initial state. Bitr's layout loader is its own reader of the format in `cellfie.md`, not cellfie's.
- Cellfie (`tools/cellfie.c`) is built like rotor and bitr, with `--include selfie.h --include tools/btor2.h`, and laid out as grid, token, cell rule, layout, simulator, model, check, main. The simulator states the rule in the `cell_*` procedures and `act`, the model in `model_rule`; both take the direction from cellfie's `reverse` flag, so one set of procedures runs and emits the rule and the inverse rule. The model is a decision tree of effects (`new_choice`, `new_effect`), by cell kind, then path or side, then instruction: keep it one, see the decisions of November 23, 2026. A grid enters cellfie as a layout or is compiled from a RISC-R binary (`compile_layout`, in the compiler section before main), and leaves it as a layout. The compiler lays wire only as combs (`lay_comb`) and every cell only once (`lay_cell`), into a list of laid cells, not onto the grid: `write_layout` writes a compiled layout from the sorted list (`sort_laid_cells`, `write_laid_cells`, `print_laid_cell`), and `materialize_grid` puts it onto a grid when a token is to run. Cellfie's own binary is compiled by cellfie on cellfie, so the compiler's inner loops count: no `get_bits`, `left_shift`, `and`, or `encode_cell` per instruction, per cell, or per character there (`classify_instruction`, `split_keys`, `put_layout_characters`), and no `zmalloc` for arrays that are written before they are read. What the compiler lays and what the hybrid simulator measures come from one plan (`plan_path`, `plan_path_combs`, `plan_regions`, `plan_strips`, `place_strips`, `plan_rows`); the rows of the path are offsets within a strip of the path (`path_pitch` rows each), laid by `lay_path_combs` and `lay_side_comb`; `place_strips` both places the strips and, with `laying_strips`, lays the combs over them; a constructor is emitted by `emit_constructor` with selfie's emitters and laid by the same `lay_layout` as any binary, with its tape as a region of memory (`construct_layout`); flight is `act_flight` in the simulator and the `flight_effect` of `model_rule`, chosen before the cell's kind; the pocket is the `pocket_*` variables next to the `token_*` ones, exchanged as a whole by `swap_contexts`, which is also how the states of the pocket are read and written (`get_state_word`), and in the model `model_pocket` (ld of a field, on the path) and `model_landing` (chosen before flight); the hybrid simulator (section before main) calls the cell rule's procedures (`act_instruction`, `act_memory`, `act_tape`, `instruction_property`) and has no rule of its own.
- Riscr is built on `selfie-riscr.h`, not `selfie.h`: `selfie.c` with `main`, `find_next_character`, `get_symbol`, `compile_assignment`, and `compile_statement` renamed by sed, as `selfie-gc.h` is generated. Riscr's procedures of these names, in its `COMPOUND ASSIGNMENTS` section, call selfie's and add the compound assignments; it compiles with `./selfie -c selfie-riscr.h tools/riscr.c`. A compound assignment is RISC-U code between markers in `s6` (`addi s6,zero,0`, and `ld`, an operation, and `sd` with `s6`), which the translator classifies as `TK_BEGIN`, `TK_UPDATE`, and `TK_NOTHING` and emits with `put_update` and `put_inverse`. Anything `put_body` learns to emit inside an expression needs its inverse in `put_inverse`. A loop without history, `from (e1) while (e2) statement`, is compiled by `compile_from` with four more markers in `s6` (`addi s6,zero,1`, `addi s6,a,2`, `addi s6,zero,3`, `addi s6,a,4`), classified as `TK_LOOP_*` by `analyze_loops`, and emitted by `put_loop_head`, `put_loop_exit`, and `put_loop_back`; gcc compiles such a program with `-D'from(e)='`.
- Testing code lives in `tests/`, never in `tools/` or `selfie.c`. The M1 harness is `tests/riscr-test.c`, built like a tool with `--include selfie-riscr.h --include riscr.h` (`riscr.h` is generated from `tools/riscr.c` as `selfie.h` is from `selfie.c`), and must itself be C\*.
- Options: `riscr` takes selfie's options plus `-t <binary>` (translate the loaded RISC-U binary into a RISC-R binary, which stays loaded), `-m <MB>` (forward) and `-rev <MB>` (forward and then backward, checking that the initial state is restored) for RISC-R binaries; there is no RISC-R flag in selfie. Rotor's options after `-` include `-riscr` (RISC-R machine model), `-inverse` (the inverse model), `-roundtrip <N>` (check inverse after forward and forward after inverse on N random states), and `-tapes`, `-tapewords`, `-syscallwords` to size the tapes. `riscr -history <MB>` sizes the history stack a translated program allocates (3072 by default), so that translated programs fit rotor's models. Bitr takes `model.btor2 [ -l binary ] [ -i file ] [ -k steps ] [ -p ]` and reports the first bad state or violated constraint with the number of instructions executed. With `-bmc <steps>` it checks all inputs symbolically (`-all` for every bad input, `-w file` to write the witness, `-dimacs prefix limit` to write the SAT instances, `-v` for progress); `model.btor2 -identity inverse.btor2` proves that the inverse model undoes the model; `model.btor2 -product other.btor2 -abstraction map.btor2` runs two models together, the first only in the steps in which the output `step` of the abstraction holds, and reports where a bad state of the abstraction says they differ; `bitr -sat file.cnf` runs its CDCL solver on a DIMACS file. Backward: `-dump file` after a concrete run writes the state in which it stops; `-state file` loads such a state into a model, whose own initial state becomes the target of `-bmc`, with the model's bad states ending a path; `-free state first count` makes a range of an array state free; `-enumerate state` has the solver enumerate the next values of a bit-vector state where they are no choice between constants. Cellfie takes, in order, `-l layout`, `-o layout`, `-f ticks` (forward until a property holds), `-b ticks` (backward), `-rev ticks` (forward and as many ticks backward, checking that the state is restored), `-btor2 width height` (the rule as `cellfie-WxH.btor2`; after `-inverse` the inverse rule, after `-noproperties` the rule without its bad states), `-check states` (simulator against model on random states), and for the layout compiler `-heap offset words`, `-stack words`, and `-i file` before `-c binary` (compile a RISC-R binary into a layout), and `-a abstraction heap-allowance stack-allowance` after it (the abstraction for bitr's product with rotor's model); `-k binary` instead of `-c binary` (a constructor for the layout of the binary) and `-window layout` (the cells of its window); `-room columns rows` before `-c` or `-h` (free cells south and east of the layout of any binary, for the binary to construct in, with a memory cell in the last column and row of the grid that says where they are), `-onto` after `-c` (store the compiled layout where the grid that cellfie itself runs on says it is free, store its token in the pocket, and land in it, which is only possible on cellfie), and `-window layout` after a run or before `-h` (write what was constructed in the room, with token and pocket); `-h binary arguments` last (hybrid simulation of the binary with the remaining arguments), after `-tapes descriptors` and `-tapewords words` if files other than the standard ones are used, and after `-memory GB` (virtual memory of the binaries booted, 4 by default, the stack at its end) if the binary needs more.

## Decisions that refine the plan

- `addi rd,rs1,imm` means `rd += rs1 + imm`, not just `rd += imm`, so register moves into zeroed registers stay one instruction.
- `mul`, `divu`, `remu`, and `sltu` are `rd ^= f(rs1, rs2)` (self-inverse) rather than `rd += f`, because with `+=` no forward program can ever uncompute a comparison or a product, so every loop would leak a register per iteration. `add`, `sub`, `addi`, `lui` stay additive, each invertible by another forward instruction.
- Paired branches: a taken transfer lands *after* its come-from (`target + 4`), so no extra branch register is needed and the step function is a bijection on all states given the static pairing. The come-from of a `beq` may test different registers; its condition must hold at the transfer, checked dynamically.
- Calls: `jal rd` requires `rd == 0` and links `pc + 4`; `jalr rd,0(rd)` is the come-from of a call and also the return, uncomputing `rd`; the come-from of a return is a `jal ra` right after the call site pointing at the callee's return `jalr`. The translator finds the callee's epilogue as the first `jalr` after its entry (M2).
- System calls take arguments in `a1-a3` and add their result into `a0`; backward execution recomputes the result from the tapes and subtracts it. `exit` leaves the state unchanged; `read` exchanges words with a lazily filled input tape that remembers where the file ended; `write` appends to an output tape and still writes the file; `openat` allocates the next descriptor and a tape per file; `brk` requires `a0 == 0`, grows the heap and returns the previous break in `a0`, zero on failure. This is the M1 addendum of November 1, 2026; it changes the system call convention that M2's wrappers must emit.
- RISC-R binaries carry `EF_RISCR` (bit 8 of `e_flags`); mipster refuses them and riscr refuses binaries without the flag, instead of switching modes silently.
- Riscr does not write the context pointer into `a6` on context switches, so registers are bit for bit reversible; context switching, and with it hypster, stays unsupported until M17, which adds the from-context into a zeroed `a6` instead.

- November 6, 2026, M3a: the RISC-R machine model is program-independent and its step function is total: on a state that violates a RISC-R rule the model still defines a next state, and a property fires in that state. - M3a refinements of the semantics: backward `brk` is only reversible on states in the image of forward `brk`, either `a0 != 0`, `a0 < brk`, `a1 == brk`, and `brk` at most the heap end, or `a0 == 0` and `a1` not a valid new break. - November 23, 2026, M6a, the cell rule (`cellfie.md` is authoritative): the grid is a torus with power-of-two sides; one tick is act, then move one cell, and backward move back, then undo. Wire is blank cells (which also cross wires), mirrors `/` and `\`, and routers, mirrors that act only if a bit of the token's pc or address is set. An instruction cell has an orientation and a mirror; it executes for a token on its path and is a mirror between its path and its side for a token that takes a branch, jumps, returns, or exchanges with memory. Every cell permutes the headings and is a bijection on the rest, so the rule is a bijection on all states and needs no constraint; bitr proves it without assuming anything.
- M6a, the token carries two words beyond pc and registers, both zero on a path: the address (origin of a transfer, or address of a memory word) and the datum (the register on its way to memory and back). In transit pc is the target and the address the origin, so a router is a merge by the origin on the way out and a split by the target on the way in, with no mode in the token. The cell at the target uncomputes the origin: a come-from `beq` or `jal` from its own pc and immediate, a `jalr` from its link register. A come-from is an instruction cell entered from the side, which is why origin and come-from being the same instruction suits the grid.
- M6a, where cellfie differs from riscr to stay total: `jalr` rotates pc, `rd`, and address instead of zeroing `rd` (the same when the address is zero); a token arriving at a come-from whose condition does not hold passes through, since a cell cannot check the other end of a wire; a division by zero leaves `rd` unchanged. Where a program stops is a property, not dynamics: `illegal-instruction`, `irreversible-link`, `division-by-zero`, `exit`, `unsupported-syscall` are bad states of the rule's model and where the simulator stops, and the rule is defined past them. The inverse rule has no properties.
- M6a, two statements of the rule, tied by a check: the simulator and the model are written separately, `-check` compares them tick by tick on random states, forward and backward, and bitr proves the model. Mutation testing: thirteen wrong rules fail the check; of eight wrong models the seven that are no bijections fail the proof, the eighth is a different bijection and fails only the check.
- M6a lesson on the shape of a model: the first model was flat, one `ite` chain per state over conditions like `on-path and is-add`, and bitr needed 155,363 paths and 2 minutes 39 seconds for one direction. As a decision tree, by kind, then path or side, then opcode, then the rules, with the same condition lines shared by all states, with the move computed from the bits of the heading rather than chosen by `ite`, and with a router's turn as an exclusive or, it is 80 paths and a quarter of a second, and 45 seconds for both directions on 64x64 cells. - November 23, 2026, M8, the layout: one row of instruction cells, every other column, and six combs. A comb is a binary tree over the addresses of its leaves, a row per level, a node being a router on the highest differing bit in the column of its first leaf and a mirror in the column of the first leaf with the bit set; it delivers a token from its root to the leaf with the token's address and collects tokens from its leaves at its root, with the same cells. Control instructions leave north and arrive from the south, `ld` and `ecall` leave south and return from the north; departures use the columns of the cells and arrivals the columns in between, so two combs share rows; the roots are connected through columns 0 to 2 around the torus. Routing, the risk the plan named largest, came down to this one structure: it needs no placement or search, tolerates sparse addresses, and never needed a change to the cell rule.

- November 23, 2026, distance, what the compiler does about it: (1) memory in strips, the lower bits of a word address select the column, the others the strip, each strip with its comb to and from its words, and two combs on their side over the strips; the number of column bits minimizes strip width plus height of all strips; (2) no wire around the torus: control turns in row 0 and goes south in column 0, memory returns north in column 2 and turns in row 1; (3) the stack first: a router turns a token if a bit is set, so in any comb set bits are far and the stack top is farthest; a token that is turned south before the router is turned east by it if the bit is set, which makes set bits near and lets the others leave south to strips placed anywhere below (`place_strips`: a stair of routers to the stack, the stack's strips first and descending, the others ascending; `lay_descending_comb` within a strip of the stack, in twice the columns). The comb from the strips is the comb to the strips, translated: same cells, west and `strip_pitch - 1` rows south.

- November 24, 2026, the path folded: the lower `path_bits` of an instruction index select the column, the others the strip; a strip of the path has the rows the whole path had (turn rows, combs north, path, combs south, entry and exit rows) plus a return row, and the path leads from the last instruction of a strip two columns east, south to the return row, west to the column west of the strips, and south and east into the next strip. West of the strips are four combs on their side (control out and in, access out and in), each over the strips that have a comb of that kind, in columns 3 on; the spines stay columns 0 to 2, and the strips of words are south of all strips of the path. `path_bits` minimizes strip width plus height of all strips, with a comb estimated at as many rows as bits.

Derived on paper, right at the first run of `make hybrid`; the invariant of two headings per wire still holds on every piece.
- The path folded, measured: selfie 1.48·10^14 to 9.43·10^13 ticks, 79 strips of 2,048 instructions and 52 rows; the examples 630-1,210 to 416-615 ticks per instruction, in strips of 64 or 128 instructions. What is left is memory that is not the stack: history and the heap behind it.

- November 24, 2026, M10, the construction ISA is `ld`: the parts of every cell have addresses, 2^61 plus part times 2^56 plus row times 2^28 plus column, and `ld` at such an address exchanges `rd` with the part (the lowest 8 bits for the kind). No new instruction, system call, or kind of cell; the encodings stay frozen. A constructor is then an ordinary RISC-R program, and so is anything else that reads or writes cells, a copier of itself included.
- M10, flight instead of wire: no wire leads to a blank cell, and a constructing arm would be cells that have to be built and taken down. The token has one more word, `token-flight`: zero, or the cell it left as 2^63 plus row times 2^28 plus column. A token whose flight is neither zero nor the cell it is at is in flight, and no cell acts on it: it turns as at a mirror in the four corners of a rectangle given by its position, its address, and its flight (south to the row of the address, east to its column, north to the row north of the cell it left, west, and south into it), and exchanges its datum with the part in the corner of its address. The instruction cell toggles the flight by exclusive or with its own position, on departure and arrival alike. Why a bijection: the predicate "in flight" is invariant under both branches (the flight act leaves position, address, and flight alone; the cell's act only sees flight zero or its own position and maps these onto each other), mirrors and the exchange are involutions, and the four turns are exclusive ors on the heading, so they commute. Bitr proves it in under a second on 19 states. All properties now require flight zero.
- M10, the constructor moves, it does not copy: its tape is memory words, the address and the value of each part of a cell that is not zero; the loop exchanges the value into a register, the register with the part, what was there back onto the tape, and the address back. No history, no garbage; backward it takes the layout apart. The compiler writes it with selfie's emitters (`emit_constructor`), boots it without a file, and gives it its tape as a region of memory at 1GB whose initial words `initial_word` computes; the window is south of the constructor and east of column 64.
- M10, the check compares files: `-window` writes the window as a layout, and with the lines of the compiled layout's token in front it must be the compiled layout byte for byte, and run. Under mipster the compiled layout differs from the native one in its stack, as M8 noted, so the mipster run compares with a layout compiled on mipster. Mutations: a simulator that misses one turn fails `-check` on 4% of random states; a rule that overwrites a cell's word instead of exchanging it fails the proof.
- M10, measured: 3,885 ticks per part for the test program, 12,628 for the running example, since the tape is twice as many words as parts in strips of the constructor's own memory, and each part is four legs to it and a flight. Not done: the constructed program does not start (the token is the constructor's), the hybrid simulator does not fly, degenerate flights (destination in the row or column of the cell left) have no property, and the tape is uncompressed.

- November 24, 2026, M11, what the fixed point is: L0 is the layout of `cellfie-r.r` that cellfie writes on the host, L1 the layout of `cellfie-r.r` that `cellfie-r.r` writes on cellfie's hybrid simulator, both with default memory (data, 64 words of stack, the standard tapes). They are files, compared with `cmp`. The layout compiler writes a file as selfie writes a binary; it does not construct. The binary that runs is the binary that is compiled, so it is translated once, with the history it needs to run (12GB).
- M11, sizes decided it: translated cellfie did not translate (1.4MB of code, `jal` reaches 1MB), did not load (selfie's `MAX_CODE_SIZE`, raised fourfold in cellfie as in riscr; an odd number of instructions, which mipster cannot load, padded by riscr now), and could not have run: the compiler allocated a grid of 134 million cells and took 31,000 RISC-U instructions per compiled instruction and 520 per character written, about 10^11 in all, against a history that fits 6·10^8 in 4GB. Now 1.5·10^9, in 8GB of history under `-memory 16`.
- M11, the cost model of C\* on mipster, measured: about 40 RISC-U instructions per procedure call and per loop iteration, whatever the procedure does. `get_bits` is five calls, `and(a, b)` three, `zmalloc` a loop over every word. Profiles by call count (`gprof` on a native build gives the same counts) predicted every step: decode per instruction (7,000 instructions), `differing_bit` scanning from bit 63 (20,000 per comb node), one `write` per character (520), mapping the binary into a context at boot (1.8 million calls for selfie's binary), a two-pass sort. The layout compiler's output never changed: every step was checked against the files of the step before.
- M11, relays in riscr (see `riscr.md`): a far call jumps to a relay in the middle of the code that makes the call and jumps back, a far long transfer jumps on from there; all far transfers are `jal zero` pairs, so no second link register is needed (a first version linked through `s7`, which nested far calls overwrite). Selfie's translation is unchanged byte for byte. One block of relays, so code up to 2MB.
- M11, a layout no longer depends on the boot level: cellfie boots a binary under the name `./cellfie` wherever it runs, and without mapping code and data into the context (`boot_binary` sets what selfie's `up_load_binary` sets, and `initial_word` takes data from the binary). `make layouts` and `make construct` still compare with mipster; they would now also pass against the native files.
- November 24, 2026, M10 and M11 joined, construction is a store: no constructor program, no tape, and no new instruction. In C\* a part of a cell is behind a pointer (`part = (uint64_t*) address; *part = value;`), selfie compiles the store to `sd`, and riscr's translation of `sd` exchanges the word at the address with the history stack and then with the value: two `ld` at the address of a part, two flights. So any translated C\* program constructs, and runs backward, with a word of history per part; M10's constructor moved parts from a tape with none. `construct_laid_cells` is that loop over the list of laid cells and refuses to run where cellfie is not booted by cellfie (the name it is booted under does not start with `>`).
- The join, what the simulators needed: a window that the compiler does not lay over (`-at`, `check_window`: south of the strips of words and east of the path, and the grid grows to hold it), and flights in the hybrid simulator: `2dx + 2dy + 2` ticks, parts of cells in a hash table of their own (`part_in_store`, 2^24 slots), a degenerate flight an `invalid-address`. `make construct` ties the formula to the event-driven simulator with one program, tick for tick.
- The join, measured: writing the layout as text is two thirds of the run (6.11·10^9 against 2.13·10^9 instructions), constructing it is 5,243,698 flights among 3.15·10^14 ticks. `cellfie()`'s option loop outgrew the reach of `beq` under selfie; the options that size things are `size_option()`.
- The join, not done: the copy has no token and does not run; the window is given, not found; nothing ran backward at full size, the hybrid simulator does not; the event-driven simulator cannot hold the grid (2^20 by 2^21 cells).
- November 25, 2026, a token for the copy is the only token: a reversible rule cannot turn the token of the program that constructed into a fresh one, its registers, program break, descriptors, and tape heads are information. Several tokens are a later layer of the plan. So the token carries a pocket, all of a token but cell and heading (13 more states, `pocket-*`), and landing exchanges the two: the child runs with the parent in its pocket, in the middle of the load that landed. This is the context switch as an exchange of M17, on the grid.
- The pocket, the two ways in: `ld` at 2^60 plus group times 2^12 plus 8 times field exchanges `rd` with a field, on the path, in one tick, and the side of that `ld` passes tokens (a permutation of headings in both cases); a flight to part 3 of a cell, which was no part, lands. C\* reaches both through a pointer, as it reaches cells.
- Landing, why it is a bijection, and what bitr says: the condition is symmetric in token and pocket (at a blank cell, one is in flight to part 3 of that cell and the other at rest, with flight and address zero), so the exchange is an involution on it; everything else maps the complement into itself, because a token in flight changes neither its flight nor its address, a token not in flight is acted on only at cells that are not blank, and the one act that makes a cell blank is by a token in flight to part 0, not 3. Mutations: landing at any cell, landing with a pocket not at rest, no second case, and a field overwritten each fail the proof; an `ld` of the pocket that also acts on the side is another bijection and fails only `-check`.
- Room, the grid's break: a program cannot know the layout it runs on, so the layout says where it ends, in a cell with a fixed address, part 1 of the cell in column and row 2^28 - 1, which is the last cell of any grid since coordinates count around the torus. `-at` and the coordinates of `-onto` are gone. The room begins south of all cells and east of all instructions, not east of all words: that is as near as a flight allows, and for cellfie on cellfie it is column 8,226 instead of 524,326.
- Implementation notes: an array state that becomes another array state has no writes for the evaluator of `tools/btor2.h`; cellfie's `step_model` copies it (`state_copies`), bitr's concrete simulator stops with an error, its proof is symbolic and covers it. A layout has the pocket after a line `#P pc address data`, written only if the pocket is not as a machine starts, and read by cellfie and by bitr. A hybrid run ends at a landing, `dx + dy + 1` ticks after the load, and writes the window, which the event-driven simulator runs on; layouts of a run with `-tapes 8` need `-tapes 8` to load. `make layouts` regenerates a cached model that is older than cellfie; a stale one with 19 states failed it.
- A token for the copy, not done: the parent does not go on and the child cannot start a child before it has emptied its pocket into its memory; the copy of cellfie has default memory, 64 words of stack and no heap, and stops at its first push, since a layout that can run the compiler has 1.8 billion memory cells; room only advances; landing only on the hybrid simulator at full size, tied to the event-driven one by `tests/cellfie-build-test.c`.

- November 26, 2026, M9 is in riscr: the plan had it in selfie, as three operators in C\* and a marker or a code generator in starc. Riscr wraps selfie's scanner and parser instead and marks the code with a register that starc never uses, so `selfie.c`, `grammar.md`, and what is taught from them stay as they are. A compound assignment is Bennett's compute, copy, uncompute at the level of the statement, as the plan first described Bennett mode: the expression is translated with its pushes, and its inverse pops them. That needs no invariant on the temporaries, which hold whatever the statement before left, and no second code generator for expressions. It costs the instructions of the expression twice.
- M9, what `^=` is: RISC-R has no exclusive or of two registers, but `mul rd,rs,one` is one, with the translation's constant 1 in `s4`. RISC-U has none at all, so the RISC-U code of `^=` is a division by zero that only marks it: reversibility is not a switch for this one statement, see rule 8.
- M9, what is checked and what is not: that `e` does not read the variable assigned to and calls no procedure, by the compiler, on the code; not that a pointer in `e` points to the word assigned to. Three wrong translators (no uncompute, a wrong inverse of `sub`, an addition for `^=`) each fail `make garbage-free`.
- M9 and rule 1: riscr compiles with selfie as long as riscr itself uses no compound assignment. M16 would write riscr's run loop with them; then either selfie learns the three operators or rule 1 becomes "compiles with selfie or with riscr". Not decided.

- November 26, 2026, M12 is measured from the bad state, not from the set of bad states: bitr cannot start from free registers and memory at the size of the examples' models (an array read at a free address is a multiplexer over the segment), so the experiment gives the checker the bad state that a forward witness reaches and frees the top of its history. It is the favourable case for backward, and backward still loses, see the plan. Decided with the user before building the full engine.
- M12, what bitr learned: a state file (name, index, value per line) as one more file interface; the target of a backward check is the model's own initial state, compared for arrays at the indices that differ before the first step and at the indices written; rotor's models report a failing fetch one instruction ahead, so backward a path takes one more step after `fetch-seg-fault` and looks again (`check_backward`); `bmc()` is at selfie's limit for a loop body, new code there goes into procedures.
- M12, what the numbers say against the plan's note on direction by free bits: free bits do not predict paths, forward or backward; paths count the control decisions that depend on free bits. The cost backward is a pointer among the free words: a free return address costs one fork, a free frame pointer makes every later access a read at a free address.

- November 27, 2026, the loop without history is Janus's, with one test: `from (e1) while (e2)`, `e1` true on entry and false after the body. It is two paired branches whose come-froms test what their origins test, so RISC-R needed nothing new, and the tests are computed and uncomputed as the expression of a compound assignment is. A wrong entry test ends in an irreversible store at run time; nothing checks it at compile time. `from` is an identifier, not a keyword, so C\* programs with a variable of that name still compile. Conditionals without history are not there.
- The bit-length loop, what it says about M12 and M15: garbage-free code makes the number of backward paths independent of the number of iterations (6 or 7 forks for 1 to 4 bits, against 18 and 68 with history), which is the plan's prediction, and the cost then is arithmetic: conflicts grow 3 to 6 times per doubling of the iterations, the 8-bit input does not finish backward in 25 minutes, and forward is 3 seconds. Forward the garbage-free loop is the more expensive one. A power-of-two division as a shift in bitr changed nothing and was not kept.

## Open after M2

- The most negative immediate cannot be negated in one instruction, so uncomputing such a constant needs two: `-2^19` for `lui`, `-2^11` for `addi`. The translator never negates constants, it pushes.
- Riscr has no replay engine (`-r`); comparing trace-based undo with trace-free backward execution is a lesson still to be written (M15).
- The history stack is a fixed 3GB region; Bennett checkpointing was not needed for selfie and is not implemented. Programs that overflow it fail at the `brk` of the prologue (exit code 20) or run into their own heap.
- The translated bootstrap still executes RISC-U's two `brk` calls, now against the program break register; `malloc` keeps its RISC-U shape. A garbage-free M9 code generator would emit RISC-R system calls directly.
- Transfers beyond the reach of `beq` cost 9 instructions at the origin and 2 per origin plus 4 at the target; selfie has 28 of them.
- `riscr.md` ends with a table of how each instruction would look with dedicated opcodes; M2 confirmed the costs that table predicts: four `^=` instructions need the scratch sequence, and `jal zero` come-froms force islands.
