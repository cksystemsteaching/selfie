Introduction to Computer Science · week 9 · station III

Self-Reference II

Will this program ever stop? One machine that can be any machine. And every interesting question about meaning.

Turing's session. The halting problem, the universal machine as the same move run forwards, Rice's theorem, and the six-theorem pattern. It ends on the positive reading: no final authority means no ceiling. Book: the Meaning chapter from The Machine, and What It Cannot Decide, to the end.

In the terminal

Does it stop?

// loop.c uint64_t c; uint64_t main() { c = 1; while (c != 0) c = c + 2; return c; }

Run it: ./selfie -c loop.c -m 1. It has not stopped yet. Will it?

You can reason: c is odd, adding 2 keeps it odd, and 0 is even — but the machine wraps at 264, so does c ever become 0? Odd plus even is odd, always, and wrapping preserves parity. It never stops.

You proved that. Could the compiler have? For this program, with effort, yes. For every program? That is today's question.

Start it and leave it running in a corner of the screen for the whole session, which is its own joke. The reasoning is worth doing on the board because it uses week 3's overflow: parity survives the wrap. Then the question, carefully: not this program, all programs.

Undecidability

Will this program ever stop? No program can always tell.

feed the decider its own description

Suppose H(P, x) decides, for every program and input, whether P halts on x.

Build D(P): ask H whether P halts on P — then do the opposite. A call, a conditional, a loop, a return. All in C*.

Now run D(D). It halts exactly if it doesn't. Contradiction. So H never existed.

Turing, 1936 — the same paper that defined the universal machine, and thus invented the computer. The limit and the machine arrived together.

Walk the figure: H, then the wrapper D, then the self-application. Say out loud that D(D) is meaningful only because a program is a number, week 5. Then the diagonal: the table of H's answers, a row per program, a column per input, D walks the diagonal and flips. Emphasise the historical detail and do not land the gloom: the next slide turns the same move over.

The same move, forwards

One machine that can be any machine.

the job moved from the wiring to the tape

A machine used to be its job — to sort instead of add you built a different machine. Turing's move: put the machine's description on the tape, as data. Then one machine U reads any description and does whatever that machine would do.

That is universality: one piece of hardware, every possible behaviour, because the behaviour arrives as notation. Your phone is not phone-shaped. It is U holding a description.

Hand a decider its own description: contradiction, no H. Hand a machine any description: every program at once, one U. One sentence, read twice.

The slide that stops the session reading as a funeral. Say what universality buys in the room's own terms: nobody here owns a calculator, a typewriter, a map and a record player as four objects. And say that mipster is U: week 6's emulator, a page per instruction group, ran every program for the machine including selfie. Then the gift and the limit are the same fact, which the next slide needs.

The general case

It is not just halting. It is every interesting question about meaning.

Rice · 1953Every non-trivial property of the behaviour of programs is undecidable. Only questions about their text are safe.
Decidable · about syntax

How long is the code? Does it parse? Does it use this library? Are the types consistent? Does it contain a loop?

Undecidable · about semantics

Is it correct? Is it equivalent to that one? Does it ever divide by zero? Is it free of infinite loops? Is it safe?

So every practical tool — a type checker, a test suite, a linter, a model checker, a fuzzer, a proof assistant — is a deliberate approximation: sound but incomplete, or complete but unsound, or exact only within a bound. Choosing which to give up is the discipline.

Rice generalises Turing and is the most useful theorem a student can own. Frame it as liberating: it tells you in advance there is no perfect analyser, so the interesting question is never can we decide this but what approximation do we choose. Last week's three terminal runs were the two columns: the error and the warning on the left, the division on the right. Week 12 builds an approximation with a stated bound.

Interlude · law

No text contains its own application.

Hart's core, and Hart's penumbra

A statute says no vehicles in the park. A car, plainly. And then the arguing starts: an ambulance, a bicycle, a memorial jeep. No redrafting removes the penumbra — only moves it. The words are finite; the situations are not.

So law stops trying to settle meaning in the text and builds an institution: courts, appeals, precedent. Not a workaround — the only available design. Rice's theorem, with no mathematics in it.

Do the vehicles as a show of hands. The point to land: the penumbra is not sloppy drafting. Finite text, unbounded situations, so interpretation is structural. Law is the oldest working example of the response the whole semester recommends: an institution that approximates a semantics no document can contain. Computer science calls it code review, type checking and testing.

One idea. Sixty years. Six theorems.

Assume a complete list. Ask each item about itself. Answer the opposite. Learn the move once and you own the century.

Give students the transferable skill: they now hold a proof technique, not six facts. It recurs twice more in this class, next week when a kernel has to isolate itself and in week 13 when a machine is asked to grade its own output.

Reframe · 3 of 5

No final authority means no ceiling.

What it forbids

A machine, a method, or a person that settles all questions. No complete rulebook, no self-certifying system, no automatic correctness.

What it opens

Mathematics is not a finished building but an open frontier; engineering is a craft rather than a lookup; and judgement — yours — never becomes redundant.

Beware of bugs in the above code; I have only proved it correct, not tried it.Donald E. Knuth, 1977

Knuth's joke is the whole session in one line: a proof is about a model of the world, and the world gets the final word. Proof and testing are two different approximations of truth, and a serious engineer uses both while trusting neither completely. Close on the program still running in the corner.

Before next week

Recommended exercises.

  1. Read the Meaning chapter from The Machine, and What It Cannot Decide to the end.
  2. Write, in C*, the wrapper D for a hypothetical H. Then explain in one paragraph why no change to mipster could make it print "this program never halts" for all such programs.
  3. Sort into text and behaviour: uses the keyword while; ever executes the while loop; contains the character /; ever divides by zero; is longer than 100 lines; prints the same as another program. Which can starc decide?
  4. Name one approximation for each of: is it free of infinite loops; is it safe; is it correct. Say what each gives up.
  5. Find the penumbra in a rule you live under — a house rule, a traffic rule, a grading rule.
