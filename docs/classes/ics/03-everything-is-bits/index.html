Introduction to Computer Science · week 3 · station I

Everything is bits.

Numbers, negative numbers, overflow, characters, text, files, images, code — one notation, and what the machine makes of it.

← ICS 02 · Size

Still station I, still no theorems, but now the bits get meanings. The thread of the session is one number, 85, which is also the letter U, which is also minus 43, which is also an address, depending on how it is read. That is the thesis of the class in miniature and it should be said as such at the end. Book: the Size chapter from Bits to Code.

Binary

85 is 1010101. Nothing else changed.

Decimal: 85 = 8·10 + 5·1. Binary: 1010101 = 1·64 + 0·32 + 1·16 + 0·8 + 1·4 + 0·2 + 1·1. Same number, a different base. The value is the meaning; the digits are the notation.

Adding works the same way in any base — carry when a column overflows its base. 1010101 + 111 = 1011100, which is 85 + 7 = 92.

Hexadecimal groups four bits into one digit: 1010101 is 0x55. Octal groups three. Both are just shorter ways to write the same bits; the machine only ever sees the bits.

85 + 7 = 92, one full adder per bit

Do the addition on the board before showing the figure, carries and all. Then the figure: seven full adders, each of which is two half adders and an OR gate, each of which is a few logic gates. This is the only piece of hardware in the class and it is here to show that arithmetic is circuits, and circuits are formulas, which week 11 will use when a program becomes a formula.

Negative numbers

Two digits, read three ways.

encoding · unsigned · signed

With two decimal digits you can encode a hundred things. Read them as 0 to 99, or read 50 to 99 as −50 to −1. Same digits. Subtraction becomes addition: 7 − 8 is 7 + 92 = 99, which is −1.

The machine does exactly this in base two: two's complement. With 64 bits, 264 encodings, read as 0 to 264−1 or as −263 to 263−1. The bits do not say which.

1010101 with seven bits is 85 unsigned — and −43 signed. Same seven bits.

The three rings are the whole idea: an encoding ring and two interpretations laid over it. Make them compute 7 minus 8 in tens complement by hand. The sentence to land is the last one on the slide, because it is the second appearance of one notation, two meanings, after last week's two kilos.

Overflow

Finite means the numbers wrap around.

With 64 bits, 264 − 1 plus 1 is 0. Nothing crashes; the carry out of the top bit is simply lost. That is an overflow, and the machine does not tell you.

Signed, the same wrap makes 263 − 1 plus 1 equal to −263: the largest positive number plus one is the most negative one.

Every integer in every program you will ever run lives in a finite box. Most of the time nobody notices. The times somebody does are famous.

$ cat examples/overflows.c // … prints UINT64_MAX + 1, INT64_MAX + 1, and what happens $ ./selfie -c examples/overflows.c -m 1 …

Run the example live and let the room see zero come out of the largest number plus one. Overflow is the first concrete instance of finite versus unbounded, which week 9 needs when the Turing machine gets an infinite tape: our machine does not have one, and this is what that costs.

Characters

1010101 is also the letter U. People in the 1960s sat down and agreed.

ASCII: seven bits, 128 characters, a table agreed in 1963. 85 is U. 48 is the digit 0, 65 is A, 97 is a, 32 is a space. The digit '0' and the number 0 are different things with different codes.

Unicode extends the table to every script, and UTF-8 encodes it in one to four bytes so that ASCII is unchanged. A byte is eight bits, a nibble four, and the figure names its ends.

a byte: 01010101 = 85 = 'U'

A byte is 85, or U, or minus 43. Three meanings, one notation, no way to tell from the bits. Have them look up their initials in the ASCII table in the assignments directory and write them in binary. Then the byte figure: the bit order matters, most significant on the left, and this convention is the only reason two machines agree.

Memory

Memory is bytes with addresses. An address is a number. So a byte can hold an address.

storage and addresses
a value read as an address: a pointer

Left: the column of bytes, numbered from the lowest address up. Right: the first genuinely computer-science idea of the session. The byte at address 0 holds 85, and 85 is also an address, so it points at the byte at 85, which holds 7, which points at the byte at 7, which holds 0. A pointer is a value read as a location, and every data structure in every program is built out of exactly this. Take the minute.

Text and files

A string is bytes in a row, ended by a zero. A file is a string with a name.

"science", NULL-terminated, at address 85

Contiguous: the letters of a word one after the other. The zero byte says where it ends, which is how a machine that only sees bytes knows a word is over.

Non-contiguous: a text is paragraphs, each contiguous, reached through pointers. A directory is names and pointers to files. A file system is a tree of directories, and a pathname is the route from the root.

All of it is bytes at addresses. The structure is in how they are read.

The string figure is the one to dwell on, because selfie's own source code is exactly this: 365,784 bytes, each an ASCII character, in a file called selfie.c. Mention the text, directory and tree figures in the book without showing all of them; the mechanism is identical.

Images, video, audio

A picture is numbers in rows. A film is pictures in a row. A sound is numbers in a row.

an image, row-major
audio, 8-bit samples

Quick, because the room believes it already; the point is only that nothing new is needed. A pixel is a few bytes, a frame is pixels in row-major order, a sample is a byte or two of amplitude, and a second of sound is forty-four thousand of them. The device does the encoding and decoding; the machine in between only ever moves bytes.

Code

And an instruction is 32 bits. Code is bytes too.

machine code, four bytes per instruction

Selfie compiles its source to 43,492 instructions of 32 bits each: 173,968 bytes of code and 14,424 bytes of data, laid out one after the other in a file.

That file is bytes at addresses, like a text or an image. The machine reads it and does what it says. Nothing in the bytes tells you whether they are code or data; the machine chapter shows what does.

$ ./selfie -c examples/hello-world.c -m 1 ./selfie: selfie compiling examples/hello-world.c to 64-bit RISC-U with 64-bit starc … ./selfie: 64-bit mipster executing 64-bit RISC-U binary examples/hello-world.c with 1MB physical memory Hello World!

Run hello world. Then say the two things this slide is for. First, code and data are the same stuff, bytes, which is the fact that makes a compiler possible, and a virus, and a machine that reads itself. Second, the file that came out of the compiler is a number, one very long one, and week 5 takes that seriously.

One notation, many meanings

1010101 is 85, and U, and −43, and an address, and half an instruction. The bits do not say which.

Everything a machine stores is a number. Everything a number means is decided by whoever reads it, and by nothing else.

Last week: one prefix, two meanings. This week: one byte, five. The gap between the notation and its meaning is not a defect of computers. It is what this class is about, and next week we start on the notations that pin meaning down.

Whatever you see on a screen could come from anywhere and mean anything.the book, Life 4

The thesis slide of the session. Say it plainly: the bits are the notation, the reading is the meaning, and there is no third thing in the machine that connects them. Week 4 introduces the formal languages whose job is exactly to connect them, by decree.
